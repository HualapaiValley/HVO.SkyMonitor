# Presentation materializer layer selections

In CameraAgent **Operations → Processing graphs**, open a graph draft and its
**Presentation materializer** panel. This panel covers the existing
`PresentationMaterializer` step at `typed-presentation-materialization-v1`.
Pipeline JSON remains authoritative.

- **Using manifest defaults** means `enabledLayerKinds` is absent or an empty
  array. Each retained manifest layer uses its existing `enabledByDefault` flag.
  Empty does not mean “hide every layer.”
- Add an **Enabled layer kinds** item to choose an explicit selection. The
  ordered controls support adding, changing, removing and moving entries with
  native keyboard-accessible selects and buttons. **Use manifest defaults**
  clears the list. Changing back to the original selection preserves unchanged
  source bytes and avoids a new draft.
- An explicit selection includes matching retained kinds even when disabled by
  default. Names are case-sensitive: `environment` is valid, `Environment` is
  not. Legacy aliases are preserved: `star-annotations`, `cardinal-directions`,
  `image-circle`, `constellations`, and `corner-annotations`. A kind and its alias
  count as the same kind for uniqueness; at most ten entries are accepted.
- `scene-annotation` retains its existing grouped matching for annotation,
  cardinal and image-circle layers. List order is preserved in JSON; the manifest
  controls composition order. The supported orbital-track kind is selectable
  only as an existing kind: selection does not add its producer or dependencies.

The panel changes which existing layers are materialized. It does not change
base/input/output variants, producer bindings, `useRichFrameFacts`, source layer
products, viewer preferences, authorization or missing-layer behavior. Required
manifest and producer dependencies must still validate; an absent optional kind
is not generated by selecting it. Invalid/null lists need an explicit correction
before saving. Unknown JSON fields and unedited alias/escape spellings survive.

Preview the changes, save a draft, validate it, and explicitly activate it.
Saving does not activate. Roll back to the previous revision through the existing
graph controls. Retained products and old revisions remain reconstructable with
their recorded inputs. The descriptor and codec are host-neutral; both hosts use
the same materialization executor. This slice adds no LogicHost editing surface.
