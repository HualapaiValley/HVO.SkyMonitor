## API and isolation

`HVO.SkyMonitor.Astronomy.Orbital.Propagation.Sgp4ObjectPropagator` is internal.
Its interface is:

```csharp
static bool TryCreate(OrbitalRecordV1 record,
    out Sgp4ObjectPropagator? propagator, out Sgp4Failure failure);
bool TryPropagate(DateTimeOffset utc,
    out OrbitalTemeState? state, out Sgp4Failure failure);
bool TryPropagateMinutes(double minutesSinceEpoch,
    out OrbitalTemeState? state, out Sgp4Failure failure);
```

Success outputs have `NotNullWhen(true)` annotations. States use the existing
internal `OrbitalTemeState` and `OrbitalVector3` carriers in km and km/s;
no serialized or public DTO was added. `Sgp4Failure` retains both adapter kind
and original integer core error. Its kinds distinguish invalid records,
initialization, propagation, nonfinite time, nonfinite converted coefficients
and nonfinite output. Every failure returns a null state/propagator.

Creation validates the normalized record and its identity, then initializes
directly using WGS72 and AFSPC `a`. Catalog text is unchanged. Mean motion is
converted by `2*pi/1440`; GP DOT by `2*pi/1440^2` and DDOT by
`2*pi/1440^3`, with no additional factors two or six. Their stored coefficients
are directly tested because the core never reads these derivatives. Optional
metadata remains on the source record; unused vendor metadata defaults do not
assert physical type, status or known element/revolution numbers.

The epoch is Gregorian midnight JD (including `.5`) plus UTC time-of-day ticks
divided by ticks per day. Day counts use the .NET proleptic Gregorian calendar;
the adapter does not call the vendor's year-limited `jday`. Known midnight
values test years 1, 1600, 1900, 2000, 2100 and 9999, including century leap
rules. These date arithmetic checks do not extend physical SGP4 qualification
to those epochs. Submillisecond time and nonzero-offset equivalents are tested.

The initialized template is private and never propagated after construction.
Every evaluation clones it, including mutable deep-space `atime/xli/xni` and
all averaged elements. Repeated, reordered, negative, fractional and concurrent
calls agree exactly with fresh initialization in near-Earth, nonresonant
deep-space, half-day resonant and synchronous resonant cases. Independent
objects receive independent templates. No propagation path reads ambient time,
files or network, or modifies caller-owned records.

`TryCreate` checks `error` even though the pinned `sgp4init` always returns true,
then verifies a finite actual epoch state. Evaluation checks both the return
value and core error before checking finite vectors. Error 6 vectors are
discarded even when populated and finite. Core codes 1, 2, 3, 4 and 6 are
exercised; no error 5 assignment is active in this source.

The issue owner must bound query intervals/evaluation budgets and reject
unsupported leap crossings before calling the adapter. The minutes overload
supports exact reference offsets; it is not a public unbounded search API.
The existing root-owned selection policy supplies the operational epoch-age
envelope. EOP and leap-table resolution remain outside this component.

[reference pack](../orbital-reference-v1/README.md) is consumed from test output
fixtures. Its 32 cases contain 641 rows: 640 finite states and expected error
3 at epoch for `33334`. All rows are tested, including the long-duration

deep-space, half-day and synchronous resonance regimes.

The 26 focused test cases also check nonzero stored DOT/DDOT using the shared
`derivative-coefficients.json`, identifiers `100000` and `999999999`, the
initializer's true-with-error behavior, later error 4, finite decay vectors
rejected for error 6, core error 1 on extreme finite time, error 2 on mean-motion
underflow, nonfinite input time, converted-coefficient overflow and successful
core returns with nonfinite vectors. A failed evaluation does not poison the
next epoch evaluation.

An early synthetic overflow assertion expected the generic nonfinite-state
failure for a nonzero-drag orbit at `double.MaxValue` minutes; the core actually
reported error 1. The test now preserves that observed core error and uses a
separate zero-drag fixture to exercise error-free nonfinite vectors. Neither
the published reference values nor their tolerances changed. Initial compiler
diagnostics also identified the documented upstream no-ops; test-only compile
and analyzer issues were corrected before the passing candidate gate.
